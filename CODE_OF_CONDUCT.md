# Community Standards

INFERNEX welcomes contributors who want to build a useful, safe and reliable native-first cybersecurity environment.

## Expected behavior

- Be respectful, patient and constructive.
- Assume good intent while addressing disagreements directly and professionally.
- Focus criticism on ideas, code and technical decisions—not people.
- Welcome newcomers and explain project-specific context when practical.
- Give and accept feedback in a professional way.
- Respect privacy. Do not publish credentials, private keys, personal information, private project material or real target data.

## Unacceptable behavior

- Harassment, threats, discrimination, intimidation or personal attacks.
- Deliberate disruption of discussions, reviews or project work.
- Publishing another person's private information without consent.
- Posting secrets, credentials or sensitive third-party data in issues, commits, pull requests or discussions.
- Pressuring contributors to perform unauthorized security testing or unsafe actions.
- Misrepresenting project capabilities, test results, permissions or review status.

## Maintainer responsibilities

Project maintainers may edit, reject or remove contributions and may temporarily or permanently restrict participation when behavior is abusive, unsafe, disruptive or inconsistent with these standards. Maintainers should explain moderation decisions when doing so is safe and practical.

## Reporting a concern

Please report community-conduct concerns privately to the project maintainers through GitHub. Do not post sensitive details publicly. If you cannot identify a private contact route, open a short issue asking the maintainers for a private reporting channel; do not include names, personal data, credentials or other sensitive evidence in that issue.

For security vulnerabilities in INFERNEX itself, follow [SECURITY.md](SECURITY.md) instead.

## Scope

These standards apply to project spaces, including issues, pull requests, code reviews, discussions and project-related events or communications. They also apply when someone is representing the project in public.

The project maintainers are responsible for interpreting and applying these standards fairly and consistently.
